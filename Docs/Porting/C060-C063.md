## C061 (medium): community bot names

- `execution/BotSpawner.ts`: `randomBotName` (draws prefix then suffix via `nextInt`) is replaced by
  `nextCandidateName`: while `bots.length < 20` returns `getRandomElf()` (random), then walks
  `COMMUNITY_FULL_ELF_NAMES`, `SPECIAL_FULL_ELF_NAMES`, `COMMUNITY_PREFIXES + " the Elf"` with a `nameIndex` that only
  advances when the candidate came from a list and was accepted. PRNG draw order matters: when source is "list" no
  random draw is consumed. Read the full file for retry/collision handling (`spawnBots` loop).
- `execution/utils/BotNames.ts` +188 lines: three name tables. Port as data in a new module (side by side with the
  existing bot names), copying the tables from `Cache/Worktrees/671c9ea4ac9d` programmatically, not by hand.
- `Util.ts` `withinInt` +1 line (verify exact change; likely an integer clamp used by name or spawn code).
- Flag: `SpecialBotNames2552`. Bot names are not hashed unless names feed into player ids/ordering; check that the
  hash covers `displayName` (clan tag/name censoring) before assuming names are irrelevant. Records are the oracle.
- Risks: the `getRandomElf` draw order and the `nameIndex` increment condition; the `withinInt` change may touch
  spawn tile selection (hash affecting).

## C062 (medium): bot behaviour and server config

- `execution/utils/BotBehavior.ts`: `shouldAttack` no longer refuses to attack humans just because the attacker is a
  Bot (`|| player.type() === Bot` removed); `attackRandomTarget` adds `|| difficulty === Easy` to the
  `random.chance(2)` skip (the Easy check is evaluated after `chance(2)` so the PRNG is still drawn when true;
  keep short-circuit order `chance(2)` first). Flag: `BotBehaviorEasyBots2693` (PR number to confirm among
  #2693 #2694 #2695 #2697 #2698). The `emoji` function is listed in the digest but shows no diff lines: ignore.
- `DefaultConfig.ts` / `Config.ts`: cloudflare, r2 and admin token accessors only. No engine behaviour: skip, but make
  sure the Rust `Config` trait is not required to mirror them.
- Risk: which Rust BotBehavior is used by the baseline (era S); the coordinator will restructure `Rules.rs` and
  `Config.rs`, so wait for the base commit.

## C063 (low): SAM hit chance

- `SAMLauncherExecution.tick`: draws `pseudoRandom.next()` once per intercept candidate, `isHit(type, random)`:
  AtomBomb always hits (the draw is still consumed), MIRVWarhead hits if `random < samWarheadHittingChance()` (0.5),
  else `random < samHittingChance()` (0.8). On a miss it shows a `SAM_MISS` message (not hashed) and the target is
  not destroyed. The old code had a `mirvWarheadTargets.length > 0` branch that is removed; read the full diff for the
  target selection order.
- Config: `samHittingChance` 0.8, `samWarheadHittingChance` 0.5 (DevConfig 1 and 1: records use the default config).
- Flag: `SamNoRng2665` removed (PR 2665).
- Risk: extra PRNG draw per SAM tick changes the stream shared with other consumers; the SAM's own `pseudoRandom`
  is per execution, so it is local. Float comparison semantics: `next()` is [0,1).
