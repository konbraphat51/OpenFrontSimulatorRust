# Porting plan: C064 to C068

Agent-only planning note (English only). Written in Phase A, before any engine edit.

## Direction of the chain

The class chain runs backwards in upstream time: C064 is v0.27.10 and its parent C059 is v0.28.4, so a child
"change" is the revert of the parent's newer behaviour. `rules.has(X)` stays true for the newer (C059) behaviour;
C064 and its descendants therefore lack the flags that C059 and the baseline carry. Read digest `-` lines as the
*parent's* behaviour, `+` lines as the class's.

Chain: C059 -> C064 -> C065 -> C066 -> C067 -> C068. Builds: C064 `2e52c0aa4193` (v0.27.10), C065 `afa3e70b6231`
(v0.27.5) / `50fe3581cc0a` (v0.27.6) / `dab04eddb465` (v0.27.8), C066 `2b606f280b86` (v0.27.2) / `cb4cf091ffd0`
(v0.27.3), C067 `5fbdea3c3965` (v0.27.0) / `d88a6ba88753` (v0.27.1), C068 `599342995c1c` (v0.27.0-beta2).

## C064 (high risk, parent C059, 31 files, 102 commits)

Hash-relevant behaviours (names after upstream PRs; flag names are proposals, check each against the final Rules.rs):

- **BotBehavior / AllianceBehavior rewrite** (#2550 enemy selection revamp, #2606 nation alliance request logic,
  #2523 nation relation exploit, #2526 no random boats to bordering enemies, #2697 bots attacking humans, #2618
  nation config rebalance). `AllianceBehavior.ts` does not exist in C064 (+0/-232), `BotBehavior.ts` is larger
  in the parent. Plan: side-by-side variant module `Execution/Utils/BotBehaviorV27.rs` (like `BotBehaviorV28`)
  selected by a single `Change` (for example `NationAllianceLogic2606`, true for C059 and newer), plus
  `FakeHumanExecution` (91 added / 62 removed lines) and `BotExecution` call-site changes. Do not thread flags
  through the new `BotBehavior`.
- **PlayerExecution cluster removal** (#2539 DFS and zero-allocation cluster calculation, #2614 linear scan
  instead of sort). C064 has the older sort-based `removeClusters` and `neighbors().some/filter`
  `surroundedBySamePlayer`. The Rust tree already has `PlayerExecutionV36.rs` and `SeveredLand.rs`: inspect
  how they are selected; likely a new flag `ClusterLinearScan2614`/`ClusterDfs2539`. Iteration order of the sort
  (JS stable sort by size descending, then `shift`) must be reproduced exactly; ties matter for hashes.
- **#2378 gold double deduction + removal of `UnitType.Construction`**: the largest structural risk
  (ConstructionExecution +33/-49, PlayerImpl, GameImpl, UnitImpl, Game.ts, UnitGrid, Factory/City/MissileSilo/
  SAM/DefensePost/Port executions). Expect a flag selecting "construction unit exists, gold deducted at
  construction start" versus the new path. Check Rust `Game.rs` for `UnitType::Construction` and the unit id
  counter (unit ids shift if construction units are created).
- **#2665 remove RNG from SAM launchers** (SAMLauncherExecution; the parent consumed PRNG draws). Changes the
  PRNG stream, so any miss shows as a desync far from the cause.
- **#2450 donations between humans after alliance**, so DonateGold/DonateTroop executions are removed in the
  parent direction (+4/-53, +2/-51); confirm which side has the alliance check.
- **#2621 MIRV price grows with launched count** (MIRVExecution, Config `unitInfo` cost, Stats). Needs a stats
  counter or a flag on cost.
- **Config**: DefaultConfig +57/-46 (#2618 nation configs, #2662 public game difficulty, constants), Config.ts,
  DevConfig. Coordinator will restructure `Config.rs`, so wait for the base commit before touching it.
- **#2622 / #2619 username validation** (`validations/username.ts`, GameRunner): affects names only, but
  check whether names enter state hashes through player ids or `nextID` calls (profane-name path calls
  different functions).
- **Smaller**: TeamAssignment (-17, clan teams, #2536/#2511), TrainStation/Railroad (#2493 edge lookup
  optimization; likely order-neutral but check iteration order), `MiniAStar.ts` (2 lines), `UnitImpl`,
  `AllianceRequestReplyExecution`, `#2541` nuke trajectory SAM intercept prediction (client only unless it
  touches `NukeExecution`, +2/-2).
- Excluded as client-only: Schemas, themes, GameView, Stats*, UserSettings.

Risks: 35 files with many small logic changes, so bisection by flag matters (`Triage.sh --bisect-flags`).
Start with `Tools/Triage.sh` on a short Public record to find the first divergence, then fix in order of
tick of first divergence. Verify the long Public records last.
